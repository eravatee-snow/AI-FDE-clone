**Treat Backfill as a classify-then-clustering task.** The backfill process first classifies each incident using the same classifier used for single incidents, then clusters only the `new` incidents to discover new categories or merge existing ones.

**Other rejects:**
- **MCP:** no named client outside the app needs to discover this capability, for now. Only real users call it, through the app.
- **Code Mode:** one model call reads one incident record of about 3 KB (measured 2.7–3.3 KB). A 200-incident backfill is 200 small calls made by code, not one model reading 200 records, so there are no large intermediate results to keep out of the context.
- **Subagent:** it reads small and produces a small result: one record in, a short JSON verdict out. The loop is in code, so there is no parent conversation to protect.
